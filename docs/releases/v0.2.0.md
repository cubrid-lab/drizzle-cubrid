## v0.2.0 (2026-03-14)

Correct package exports and transaction handling, with expanded usage documentation. TypeScript code that imported drizzle-orm's MySQL column classes, builder types or column config types from `drizzle-cubrid` must import them from `drizzle-orm/mysql-core` instead.

### Upgrade notes

- The package root no longer re-exports drizzle-orm's MySQL column classes, builder types and column config types (for example `MySqlColumn`, `MySqlIntBuilder`, `AnyMySqlColumn`, `ReferenceConfig` and `CustomTypeParams`); these were type-only exports in v0.1.0 and never existed at runtime. They are still importable from `drizzle-orm/mysql-core`.
- With a client that has `beginTransaction()`, `db.transaction(fn, { accessMode, withConsistentSnapshot })` no longer sends `START TRANSACTION` options; only the `SET TRANSACTION` isolation level is sent before `beginTransaction()`.

### Bug Fixes

- Export the standard column builders (`int`, `varchar` and others) from the package root at runtime in both the ESM and CommonJS builds by using explicit named re-exports ([4e74f36](https://github.com/cubrid-lab/drizzle-cubrid/commit/4e74f365)) by @yeongseon
- Run `db.transaction()` through the client's `beginTransaction()`/`commit()`/`rollback()` when it provides them; other clients get the same SQL statements as in v0.1.0 ([4e74f36](https://github.com/cubrid-lab/drizzle-cubrid/commit/4e74f365)) by @yeongseon
