## v0.3.0 (2026-11-20)

The root entry `drizzle-cubrid` is now the CUBRID-native dialect, with selects, writes, transactions, relational queries, streaming and schema migrations built for CUBRID instead of Drizzle's MySQL classes. Code written for 0.x must change its imports to `drizzle-cubrid/legacy` (deprecated, removed in 1.0) or move to the native API, and date and time columns are now read only through a client that decodes in UTC (`timezone: 'utc'` or `TZ=UTC`).

### Upgrade notes

- **Breaking: the root entry is the native dialect.** `drizzle-cubrid` now exports what `drizzle-cubrid/native` exported, plus Drizzle's operators (`eq`, `and`, `sql`, …) as before. To keep the 0.x API unchanged, replace each `'drizzle-cubrid'` import with `'drizzle-cubrid/legacy'`; [docs/MIGRATING_FROM_0X.md](https://github.com/cubrid-lab/drizzle-cubrid/blob/v0.3.0/docs/MIGRATING_FROM_0X.md) has the import-by-import mapping and the behaviour differences ([#254](https://github.com/cubrid-lab/drizzle-cubrid/pull/254)) by @yeongseon
- **Breaking:** without that import change, 0.x code fails loudly or changes meaning. Same-named exports (`drizzle`, `cubridTable`, `int`, `varchar`, `set`, …) are now the native ones, and some 0.x usages compile unchanged and run with native semantics. 0.x-only names (`cubridSet`, `cubridMultiset`, `cubridSequence`, `customType`, `tinyint`, `mediumint`, `serial`, `year`, `real`, the `text` family and `CubridPreparedQuery`) are placeholders that do not compile when called and throw `CubridRemovedExportError` naming the replacement; `mysqlEnum` and the 0.x types are no longer exported from the root ([#254](https://github.com/cubrid-lab/drizzle-cubrid/pull/254))
- **Breaking: date and time columns assume a UTC wall clock**, as in Drizzle's MySQL convention. Selecting them through a client that decodes in the local zone, in a non-UTC process, is refused before the query is sent; create the client with `timezone: 'utc'` or run with `TZ=UTC`. `date()` returns midnight UTC, and `mode: 'string'` columns return strings ([#209](https://github.com/cubrid-lab/drizzle-cubrid/pull/209), [#214](https://github.com/cubrid-lab/drizzle-cubrid/pull/214))
- **Breaking (0.x API):** `binary()` and `varbinary()` now throw when called, so a 0.x schema module that declares such a column fails when loaded; use the native builders, which read and write `Buffer` values ([#251](https://github.com/cubrid-lab/drizzle-cubrid/pull/251))
- **Breaking (0.x API):** `monetary()` returns the declared `string` instead of a number ([#221](https://github.com/cubrid-lab/drizzle-cubrid/pull/221)); relational queries using `with` are refused before sending, including in `mode: "planetscale"`, where some queries used to succeed ([#206](https://github.com/cubrid-lab/drizzle-cubrid/pull/206))
- **Custom clients:** values are now sent as typed binds by default. `drizzle()` throws at construction for a client without `queryPrepared()` (or with `execute()` but no `executePrepared()`); pass `binding: 'literal'` to keep SQL literals. Clients must return array rows for `rowMode: 'array'`, and a client's `transaction` method must accept `(callback, options?)` ([#204](https://github.com/cubrid-lab/drizzle-cubrid/pull/204), [#197](https://github.com/cubrid-lab/drizzle-cubrid/pull/197), [#195](https://github.com/cubrid-lab/drizzle-cubrid/pull/195))
- **Transactions (0.x API):** `accessMode`, `withConsistentSnapshot` and `isolationLevel: "read uncommitted"` are rejected because CUBRID does not support them ([#195](https://github.com/cubrid-lab/drizzle-cubrid/pull/195))
- **Peer dependencies are now bounded:** `drizzle-orm` `>=0.38.0` → `>=0.44.1 <0.46.0` (older versions fail to type-check) and `cubrid-client` `>=0.1.0` → `>=1.4.0 <2.0.0`, the version verified against a real CUBRID server. Node.js `>=18.0.0` is unchanged ([#196](https://github.com/cubrid-lab/drizzle-cubrid/pull/196))
- **Exports map:** besides `.`, the package now exports `./legacy`, `./native` (alias of the root, same module), `./migrator` and `./native/migrator` (aliases of each other). Every entry uses nested `import`/`require` conditions, so CommonJS consumers get `.d.cts` declarations, and `typesVersions` covers `moduleResolution: node10` ([#229](https://github.com/cubrid-lab/drizzle-cubrid/pull/229), [#244](https://github.com/cubrid-lab/drizzle-cubrid/pull/244), [#254](https://github.com/cubrid-lab/drizzle-cubrid/pull/254))

### Compatibility

- Verified on CUBRID 11.4: the publish workflow gates the packed tarball on the live CUBRID 11.4 suite with both the lockfile and the floor peer versions, plus a Node 18 consumer; unit tests run on Node 20 and 22. See [docs/COMPATIBILITY.md](https://github.com/cubrid-lab/drizzle-cubrid/blob/v0.3.0/docs/COMPATIBILITY.md)
- The package now ships `THIRD_PARTY_NOTICES.md`: parts of two 0.x files that closely follow drizzle-orm's code carry an Apache-2.0 attribution, while the project license stays MIT. The native dialect contains no copied drizzle-orm code ([#256](https://github.com/cubrid-lab/drizzle-cubrid/pull/256))
- The npm `repository`, `bugs` and `homepage` fields point to `cubrid-lab/drizzle-cubrid`, and the description states that this is a community-maintained, not an official Drizzle, project ([#188](https://github.com/cubrid-lab/drizzle-cubrid/pull/188), [#256](https://github.com/cubrid-lab/drizzle-cubrid/pull/256))

### Features

- Native tables and column builders with CUBRID SQL types and exact codecs: exact `bigint` and `numeric` modes, `boolean` as SMALLINT, UTC date and time types, `monetary`, and `set`/`multiset`/`sequence` with per-element codecs ([#229](https://github.com/cubrid-lab/drizzle-cubrid/pull/229)) by @yeongseon
- Native `drizzle(client)` with a SELECT builder (joins, grouping, `for('update')`, subqueries, `prepare()`), plus `insert()`, `update()` and `delete()` that return `affectedRows` and `lastInsertId` and support `onDuplicateKeyUpdate()` and `$returningId()` ([#230](https://github.com/cubrid-lab/drizzle-cubrid/pull/230), [#231](https://github.com/cubrid-lab/drizzle-cubrid/pull/231)) by @yeongseon
- Native `db.transaction()` on cubrid-client's `transaction()`, with nested transactions as savepoints and `isolationLevel` ([#232](https://github.com/cubrid-lab/drizzle-cubrid/pull/232)) by @yeongseon
- Set operations (`union`, `intersect`, `except` and their `All` forms) and scalar subqueries as selected fields ([#235](https://github.com/cubrid-lab/drizzle-cubrid/pull/235)) by @yeongseon
- Relational queries (`db.query.<table>.findMany()`/`findFirst()`) with `with` to any depth, loaded in batched `IN (...)` statements rather than one per parent, read from one snapshot by default (`relationalReads` option) ([#236](https://github.com/cubrid-lab/drizzle-cubrid/pull/236)) by @yeongseon
- `iterator()` streaming of selects through cubrid-client's `stream()`, closing the cursor on `break` or abort, and `prepare()` for relational queries. Under the default typed binding, streaming requires `{ literal: true }` because cubrid-client 1.4 streams with literal values only ([#243](https://github.com/cubrid-lab/drizzle-cubrid/pull/243)) by @yeongseon
- Experimental CUBRID-native schema migrations: `migrate()` from `drizzle-cubrid/migrator` applies numbered `.sql` files, each in its own transaction with a checksum record and a lock against concurrent runs. `generateInitialMigration()` writes the first migration. MySQL or drizzle-kit SQL is refused, and schema diffing is not provided; see [docs/MIGRATIONS.md](https://github.com/cubrid-lab/drizzle-cubrid/blob/v0.3.0/docs/MIGRATIONS.md) ([#244](https://github.com/cubrid-lab/drizzle-cubrid/pull/244)) by @yeongseon
- Indexes, unique indexes and foreign keys (`index()`, `uniqueIndex()`, `foreignKey()`, `.references()`), with `ON DELETE`/`ON UPDATE` actions limited to what CUBRID 11.4 accepts and emitted by `generateInitialMigration()` ([#250](https://github.com/cubrid-lab/drizzle-cubrid/pull/250)) by @yeongseon
- `binary({ length })` and `varbinary({ length })` as CUBRID `BIT`/`BIT VARYING`, read and written as `Buffer` values ([#251](https://github.com/cubrid-lab/drizzle-cubrid/pull/251)) by @yeongseon

### Bug Fixes

- 0.x transactions run on a connection owned by cubrid-client's `transaction()`, so concurrent queries can no longer join, commit or roll back another request's transaction ([#195](https://github.com/cubrid-lab/drizzle-cubrid/pull/195)) by @yeongseon
- Joins whose tables share column names return each table's own values, because selected fields are mapped by position from array rows ([#197](https://github.com/cubrid-lab/drizzle-cubrid/pull/197)) by @yeongseon
- `insert`, `update` and `delete` report `affectedRows` and `lastInsertId`, and `$returningId()` returns the key of a one-row INSERT, with `bigint` keys kept exact ([#198](https://github.com/cubrid-lab/drizzle-cubrid/pull/198)) by @yeongseon
- SET, MULTISET and SEQUENCE values are written as typed collection literals and read as arrays; writes used to fail and reads parsed arrays as text ([#201](https://github.com/cubrid-lab/drizzle-cubrid/pull/201), [#204](https://github.com/cubrid-lab/drizzle-cubrid/pull/204)) by @yeongseon
- Statement values are sent as typed binds instead of being written into the SQL text ([#204](https://github.com/cubrid-lab/drizzle-cubrid/pull/204)) by @yeongseon
- `db.$count()` works on CUBRID instead of failing with `SqlSyntaxError` ([#205](https://github.com/cubrid-lab/drizzle-cubrid/pull/205)) by @yeongseon
- `datetime`, `timestamp`, `date` and `time` columns read cubrid-client's `Date` values: `datetime`/`timestamp` selects no longer throw `value.replace is not a function`, and `date()` is no longer shifted by the process's UTC offset ([#209](https://github.com/cubrid-lab/drizzle-cubrid/pull/209)) by @yeongseon
- SQL that CUBRID 11.4 always rejects (`ilike()`, `.offset()` without `.limit()`, lateral joins, `.for('share')`, `insert().ignore()`, `delete().orderBy()`) is refused while the query is built, with an error naming the alternative ([#218](https://github.com/cubrid-lab/drizzle-cubrid/pull/218)) by @yeongseon
- `inArray()`/`notInArray()` with two or more values or placeholders on a CHAR column match the right rows under typed binds, in both the native and the 0.x API ([#238](https://github.com/cubrid-lab/drizzle-cubrid/pull/238), [#240](https://github.com/cubrid-lab/drizzle-cubrid/pull/240)) by @yeongseon
- The published declarations no longer name `AbortSignal`, so consumers without the DOM lib or `@types/node` type-check with `skipLibCheck: false`. `iterator()`'s `signal` is typed with the new `CubridAbortSignal` ([#255](https://github.com/cubrid-lab/drizzle-cubrid/pull/255)) by @yeongseon

### Deprecated

- The 0.x API, now `drizzle-cubrid/legacy`, is deprecated and will be removed in 1.0; until then it gets security and data-correctness fixes only. Loading it emits one `DeprecationWarning` per process with code `DRIZZLE_CUBRID_LEGACY`, and every legacy export carries a `@deprecated` note naming its native replacement. The root entry and `drizzle-cubrid/native` never warn ([#254](https://github.com/cubrid-lab/drizzle-cubrid/pull/254)) by @yeongseon
