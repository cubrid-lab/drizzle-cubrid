## v0.3.2 (2026-11-23)

TypeScript projects that include `@types/node` can now pass a cubrid-client client or pool to `drizzle()`: in 0.3.1 `drizzle(createClient(...))` and `drizzle(createPool(...))` failed to type-check with an argument-type error, in both the root and `drizzle-cubrid/legacy` entries. Queries ran correctly at runtime; upgrading removes the type error without code changes.

### Compatibility

- Peer ranges are unchanged: `drizzle-orm` `>=0.44.1 <0.46.0`, `cubrid-client` `>=1.4.0 <2.0.0`, Node.js `>=18.0.0`. The emitted SQL, exports map and migration behavior are unchanged.
- The release gate runs the packed tarball on live CUBRID 11.4 with the floor peers (cubrid-client 1.4.0) and the lockfile peers, which are now cubrid-client 1.6.0. Fault injection runs in CI, not in the release gate, and now runs on 1.6.0 only; the 1.4.0 floor is not fault-tested. See [docs/COMPATIBILITY.md](https://github.com/cubrid-lab/drizzle-cubrid/blob/v0.3.2/docs/COMPATIBILITY.md)

### Bug Fixes

- `drizzle()` accepts cubrid-client's `CubridClient`, `CubridPool`, transaction clients, pool connections and transaction scopes under `@types/node`, whether `skipLibCheck` is on or off. The `params` argument of the client interfaces drizzle-cubrid declares (`CubridQueryable`, `CubridNativeClient`) is now `readonly unknown[] | undefined`, matching cubrid-client; custom clients that declare `params: readonly unknown[]` still type-check ([#271](https://github.com/cubrid-lab/drizzle-cubrid/pull/271), closes [#270](https://github.com/cubrid-lab/drizzle-cubrid/issues/270)) by @yeongseon
- The `iterator()` errors no longer wrongly say that cubrid-client's transaction clients lack `stream()`; the error for a client without `stream()` now says which cubrid-client versions provide it ([#271](https://github.com/cubrid-lab/drizzle-cubrid/pull/271)) by @yeongseon

### Tests

- The packed-package declaration check no longer ignores errors reported in cubrid-client's declarations, and it type-checks real cubrid-client clients, pools and transaction clients passed to both `drizzle()` entries ([#271](https://github.com/cubrid-lab/drizzle-cubrid/pull/271))
